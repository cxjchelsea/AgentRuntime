## 原有资料保留区：历史设计与审查证据

旧资料仍在 [可复用Agent_Runtime平台设计](../可复用Agent_Runtime平台设计/) 下，按原路径保留以维持历史提交、审查和测试追溯。它们属于以下类别：

1. `M0-M9实现方案/`：各模块历史详细设计、曾经的冻结子设计。
2. `缺口设计/CA-*`、`M5-IU*`、`*Review*`：按时间形成的整改、实现、审查和授权证据。
3. `缺口设计/*Canonical Registry*`、`*Schema Registry*`、`*Runtime 运行不变量*`：既有冻结契约/约束资料，不能因“历史文件夹”名称随意忽略；若与当前代码冲突应进行显式兼容性审查。
4. `0-*`、`1-*`、`2-*`：原 Runtime-first 的全局设计与模块映射，记录架构演进，**不再作为当前产品总纲**。

### 如何判断某份旧文件是否“过期”

- Review V1.0 说 BLOCKED、V1.1 说 READY：这是**不同时间点的历史证据**，不是应删除其中之一。
- 接口与冻结契约可能仍被代码/测试引用：不未经验证删除。
- 仅旧的导航入口、无独立证据价值且被本 README 完全替代的内容可以删除。
- 大规模物理移动或删除，需要先生成全仓库引用映射，确认 CI、代码和外部链接影响后单独 PR 审批。
