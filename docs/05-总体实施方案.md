# 通用 Agent 系统总体实施方案与开发路线 V1.0

> **产品实现权威入口**：与 [总体架构 V2.1](01-总体架构.md) 成对维护。  
> **版本**：V1.0（2026-10-09）｜**状态：设计候选，允许进入 GA-01 详细设计；不等于授权生产执行或冻结全部合同。**  
> 源码基线：main `01347c62083cdb30b8a149d37bb979b373ded9d3`。

## 0. 实施原则与实际完成定义

- 不按 M0→M9 依次重做；沿着任务级可运行能力建设。
- 优先用现有 `RuntimeUnderstandingEngine`、`DefaultM4Planner`、`RuntimePlanValidatorAdapter`、`RuntimePolicyRecheckerAdapter`、M5 Executor/Aggregator、现有 State/Trace/Registry。
- 新增最少的 Agent Run/Loop、Observation/Continuation 与 Package Assembly，避免重复核心服务。
- 在每个单元保留低成本、可重复、无外部副作用的 E2E；真实模型与真实非危险工具随后验证，但 M6 B3 授权之前**不能**进行生产意义的正向外部副作用调用。
- 一个交付单元分成：设计/接口 → 实现 → pytest/mypy/ruff → Integration/E2E → 证据和现状更新。安全和冻结合同修改才要求专门独立审查。
- 验证术语：`DESIGNED`、`IMPLEMENTED`、`E2E_VERIFIED`、`PRODUCTION_AUTHORIZED` 不可混用。

## 1. 全局开发路线

```text
GA-00（目标架构/资产盘点）
    │
    ├─ GA-01（最小 Agent Loop / 完全隔离）
    │       ├─ GA-01A 控制流与合约兼容设计（必要）
    │       ├─ GA-01B 决策/观察/预算闭环
    │       └─ GA-01C Mock 工具负向与 E2E
    │
    └─ GA-02（Domain Package Loader/Assembly；接口稳定后可并行）
               │
               └──────┐
GA-01 ────────────────┼─> GA-03（双领域核心复用 E2E）
                      │
                      └─> GA-04（深化复用 Runtime 能力；部分前置于 GA-01）
                                │
                                └─> GA-05（反思、记忆、长任务、Replan）
                                          │
                                          └─> GA-06（生产认证和真实应用接入）
```

## 2. Development Units 与验收

### GA-00：目标架构与实施准备

**目标**：完整产品层次、现有代码复用矩阵、权限/验证限制、实施方案、风险开放项清晰且可追溯。

**输入**：`runtime/`、`tests/`、历史 Closure 和冻结契约。  
**直接复用**：现有代码资产清单，不修改实现。  
**新/改**：`docs/01-总体架构.md`、`docs/05-总体实施方案.md`、`docs/06-设计兼容性审查.md` 与入口更新。  
**测试**：文件引用和源码路径核查、文档差异范围核查；无 production test 行为变化。  
**DoD**：有明确“架构目标≠已实现”、重大决策和开放风险；审查与冻结状态分开。  
**风险**：文档过早将候选接口视为正式合同。  
**阻塞**：GA-01A 的架构入口需要本方案；GA-02 可在接口明确后开始。

### GA-01A：Agent Loop 详细设计与安全边界

**目标**：实现前固定最小 Call Graph，而不是直接新增新 `Planner`。

- 设计候选 `AgentRunCoordinator`、`IterationContext`、`ObservationAdapter`、`ContinuationPolicy`；查明 M3→M4→M5→M6 的组合点。
- 复用 `runtime/interfaces/planning.py` 的 Planner/Validator/Rechecker 与 `runtime/interfaces/execution.py` 的 ExecutionEngine 合同；M5 必须消费 `ApprovedActionPlan`。
- **强制设计隔离**：以 Fake Model + Fake/Mock Tool 和隔离 No-Side-Effect Driver 测闭环；不将测试 Observation 当作 `ValidatedResult` 的生产签发权限。
- 明确冻结 `ActionPlanDraft`/ `ApprovedActionPlan`/ `ExecutionResult`/ `ValidatedResult` 不变；任何改动另开兼容审查。
- 确定固定主链 `RuntimeOrchestrator.run()` 不可直接重复调用，因包含 Response/Update；GA-01A 要给出可接受的适配点与用例。

**输入依赖**：GA-00 的 D-01、D-02。  
**交付物**：精确接口/数据流、预算/停止表、M6 安全测试绑定规则、最小事件定义、测试矩阵。  
**Unit**：非法模型 Action、缺失 binding、计划未批准、超预算、NoGrant、UNKNOWN。  
**Integration**：双策略路径、按原 M4 准入。  
**E2E**：使用无副作用注入进行计划→工具观察→再次决策→完成的先行验收样例。  
**DoD**：不存在第二套 Tool 执行权威；不能绕 M4/M6；设计评审至少确认两条关键边界。  
**阻塞**：GA-01B；**允许 GA-02 仅开展不影响合同的包格式探索**。  
**风险**：M6 只有 NoGrant，无法合法走生产正向链，必须明确 test-only 隔离。

### GA-01B：最小 Loop 实现

**目标**：至少两次结构化决策、一次 Tool 调用、一次经授权的测试 Observation、可靠 Finish。

**复用**：M3 Engine、M4 DefaultM4Planner/Validator/Rechecker、M5 Registry/Resolution/Execution；测试需按 GA-01A 设计的 Adapter 边界装配。  
**新增**：AgentRunCoordinator、LoopBudget、ContinuationPolicy、ObservationAdapter、RunTrace 关联（最小实现）；不要求立即持久化所有长期任务字段。  
**功能**：提交 goal、轮次上限、动作合法性核验、超时/取消、工具结果重入、完成条件。  
**Unit**：预算耗尽、反复相同行为、UNKNOWN、WAITING、Tool 失败、结束一次且只一次、非法计划拒绝。  
**Integration**：真实 M4 审批与 Fake 执行路径接线、Trace ID 关联。  
**E2E**：确定性脚本模型在前一轮选择工具，观察后下一轮选择 FINISH（不借助“预置成功回复”伪造工具事实）。  
**DoD**：多轮轨迹可复现、负例 fail-closed、不改变现有固定主链回归。  
**阻塞**：GA-01C/GA-03。  
**风险**：在 Loop 内错误重复外部副作用；严格 Mock 调用次数验证。

### GA-01C：模型适配与首次运行验收

**目标**：证明不是纯 Mock 图表，也不是只能跑固定脚本。

**新增**：结构化 Model Provider Adapter、Prompt Assembly 最小实现、错误/成本统计；真实模型调用单独环境验证，**工具仍为非副作用模拟**。  
**Unit**：格式错误、额外字段、幻觉 Tool ID、超时、不可用模型、Token 预算。  
**Integration**：M3/M4 既有受限 Model Protocol 对接模型供应商；不让 LLM 替代 Policy。  
**E2E**：同一低风险任务分别跑 Fake Model 和真实模型；模型稳定性作为统计指标，不以一次示例宣告可靠。  
**DoD**：可重复运行命令、结构化 Trace、至少一种真实模型的隔离成功样例（如因凭证不可用明确 `NOT_VERIFIED`，不得假报完成）。  
**风险**：真实模型可变性、成本和 Prompt 注入。

### GA-02：Domain Package 装配

**目标**：可按 `domain_id + exact version` 加载完整包并冻结依赖。

**复用**：`runtime/registries/domain.py`、`prompt.py`、Tool/Skill/Workflow/Strategy Registry 和 Schema Registry。  
**新增**：PackageLoader、DependencyResolver、DomainBinding、Prompt/Knowledge/Rule/State Policy Assembly；仅在 GA-02 设计时冻结最小 Manifest 扩展。  
**Unit**：版本错配、缺依赖、重复 ID、未授权工具、错误 schema、跨身份缓存拒绝。  
**Integration**：M4 合法候选集合/M5 Registry 精确绑定，Prompt 版本一同固定。  
**E2E**：在一个 Core 中完成 Package A、B 加载并报告 binding 版本、可用 Action 集合；不要求此时完成两类任务。  
**DoD**：不改 Core、包切换有效，失效闭合。  
**阻塞**：GA-03；可与 GA-01C 部分并行。  
**风险**：把配置注册误当真正装配。

### GA-03：Cross-Domain E2E

**目标**：证明通用性的最低可信证据。

**领域建议**：教育学习规划 + 通用资料问答（优先低风险；医疗知识答疑可作为扩展测试但不做医疗诊断）。  
**复用**：GA-01 Loop + GA-02 Loader + M3/M4/M5。  
**新增**：两个 Domain Package、fixture、跨域隔离 Eval 数据集。  
**Unit**：每包 Prompt/Tool/Rule/Knowledge/State schema 检查。  
**Integration**：绑定切换、缓存/Session Scope、Context/Memory 独立。  
**E2E**：两类任务在同一 Core 上成功；不能借助修改 Core 或隐藏的环境专用 if/else。  
**DoD**：可重复结果、Trace 完整、无跨包数据污染。  
**阻塞**：GA-05 和生产通用性声明。  
**风险**：示例过于相似，不能证明真实差异。

### GA-04：Runtime 深度集成与完整授权边界

**目标**：逐项接入现有 M5 可靠性、M6 验证、取消/中断恢复、任务级 Trace；不得让新 Loop 直接替代 M5 Recovery。

**输入**：GA-01/03 成果与 G1/G2 NoGrant 约束。  
**复用**：M5 IU6..IU10、M6 Facade、现有 Trace。  
**新增/修改**：按精确差距加少量 Adapter、可能的显式 M6 grant 方案（需独立批准）。  
**Unit**：重复调用防护、幂等、Owner Fencing、取消日志终态、失败后不得自动重规划危险动作。  
**Integration**：中断恢复与 Loop 继续严格区分；验证授权链从 Executed→Validated。  
**E2E**：多步+失败/恢复场景，完整轨迹和安全否定。  
**DoD**：业务行为闭环、安全不变量和原 Runtime 回归均通过；生产 Grant 不可因 Demo 自动获得。  
**阻塞**：GA-06。  
**风险**：GA-01 测试便利路径被误用在生产。

### GA-05：高级 Agent 行为与记忆

**目标**：在已验证的最小 Agent 上扩展多步规划、可信 Reflection/Replan、跨轮 Task、Context/Memory 治理。

**复用**：M4 `ReplanEntryRequest`、M5 Checkpoint/Recovery、`MemoryContext`、`StateMemoryUpdater` 合同。  
**新增**：反思策略、Replan Control、任务状态持久化、长期记忆 Provider/Store、记忆失效时效/删除机制。  
**Unit**：过期记忆/错域记忆拒绝、工具失败 Replan、新目标冲突、重复重规划熔断。  
**Integration**：跨轮恢复与 M5 内部恢复协同、Memory 授权读写、Trace。  
**E2E**：任务中断→继续，不重复已完成副作用；旧偏好失效后不继续污染回答。  
**DoD**：有故障注入/恢复和记忆一致性证据；不是只新增 Memory schema。  
**阻塞**：复杂生产任务。  
**风险**：状态双重权威或不一致。

### GA-06：Production Agent

**目标**：可被独立 Application 装配部署，并且每个真实副作用经过正向授权。

**依赖**：已完成相应生产安全设计、M6 B3 正向验证授权、生产 Composition Root、身份隔离、凭据管理。  
**交付**：可运维应用、权限策略、实际工具与模型、追踪/告警、回归和演练。  
**Unit/Integration**：权限负测、真实 API 只读/写入区分、回滚/失效注入、部署配置检查。  
**E2E**：非危险真实工具端到端；对高风险动作增加确认和审计。  
**DoD**：`PRODUCTION_AUTHORIZED` 的明确证据，不再用 Source/Mock Closure 宣告。  
**风险**：生产安全和合规证据不足；未通过前不进入生产。

## 3. 补充实施流：继承 V1.0 的 K0、插件和业务接入流程

V2.1 明确：GA 是**平台建设流**，新 Agent 创建流程是**平台使用流**。两者可以关联，但不能合并为同一列表。

| 继承旧版能力 | 最早落地单元 | 需复用/核验的现有实现 | 新增产物与真正的验收 |
|---|---|---|---|
| Domain Extension vs Business Package 分工 | GA-02 | `DomainManifest`、Registry/Schema | 一个 Package 中区分机制资产和产品资产；版本关系、冲突/缺失拒绝 |
| Rule/Policy 插件与优先级 | GA-02 / GA-04 | `policy_management`、`constraint_management`、`priority_management`、`safety` | 实测 Safety deny 与 Domain/Planner 冲突，明确执行优先级；不可仅复制旧定义 |
| Workflow 插件与 Agent Loop 协作 | GA-02 / GA-03 / GA-04 | `WorkflowImplementation`、M5 调度/恢复 | 无 Workflow 与有 Workflow 的任务各一个；实例恢复与 Agent Replan 不互相夺权 |
| Capability Contract / Implementation 可替换 | GA-02 / GA-03 | M5 `ExecutionImplementationResolver`、version pinning、Registry | 同语义能力两种实现替换不改 Core，兼容/不兼容版本正反测试 |
| 四层 Prompt + Model 结构化输出 | GA-01C / GA-02 | M3/M4 model protocol、PromptRegistry | 多层 Prompt 装配、版本审计、模型输出越权拦截 |
| K0 Ingestion/Index/Retrieval/Rerank/Evidence | GA-02 先定义绑定；GA-03 首次检索 E2E；GA-05 补治理 | `knowledge_planning.py`、K0 旧详细设计 | 真正检索结果与来源 Evidence 注入；源有效性/过期/域隔离负测 |
| Core/Domain Schema 与 Identity | GA-01A / GA-02 | `runtime/contracts`、Schema Registry、DomainExtensions | 无合同破坏、跨包身份隔离、拒绝 `elder_id` 等进入 Core |
| Core + Domain 两级 Eval | GA-01B / GA-03 | `tests/`、历史 E2E Eval 规范 | Loop 运行轨迹和两种业务独立 Dataset/Truth 用例 |
| 创建新 Agent 的 12 步业务接入流程 | GA-03 | GA-02 Loader + GA-01 Loop | 用文档化模板新建第二 Domain，不修改 Core，验证全部 12 步有证据 |

**K0 独立交付准则**：不能仅因 M4 有 KnowledgePlan 就声称 K0 实现完成；必须检查 Index、Retriever、Rerank、Evidence、Version/Validity。允许 GA-03 先用小型真实检索 fixture，但应与 Fake Lookup 明确区分。

**Plugin 兼容准则**：同 Capability 实现换版必须证明不改变输入输出/权限/幂等/证据，不兼容版本必须 fail-closed；不允许“换了实现结果表面正常”替代合同测试。

**平台成功准则**：两个不同领域跑通相同 Core 后，还需展示新业务 Agent 的创建操作清单、版本绑定信息和 Eval，让使用者能够重复接入第三个领域，而不是只能复制代码。

## 4. 端到端 Evaluation 与最低度量

| 维度 | 指标/测试 | 最低进入条件 |
|---|---|---|
| Loop 有效性 | 至少 2 次决策、至少 1 次工具观察、明确停止 | GA-01B E2E |
| 行动合法性 | 所有 Tool 与 Plan/Policy 对应 | 100% 不合法调用被拒绝 |
| 工具真值 | Verified vs raw Execution 分离 | UNKNOWN 不被伪装成功 |
| 停止/效率 | max iterations/calls/time/tokens、重复抑制 | 上限测试全部通过 |
| 异常/安全 | deny/cancel/failure/timeout/unknown | Fail-closed 负测通过 |
| 两领域复用 | 同 Core/不同 Domain、无需源码修改 | GA-03 两类差异任务通过 |
| 状态隔离 | identity/domain/version 缓存和记忆隔离 | 跨域错误读取为 0 |
| 回归可靠性 | pytest/mypy/ruff/format + 精确 commit | 同一 HEAD 四项门禁 |
| 生产准备 | 授权、组合根、部署、运行报告 | GA-06 独立验收 |

任务成功率等统计指标应由固定 Eval 数据集和多次执行计算；目前**尚无真实统计证据**，不预填虚假的百分比。

## 5. 优先级和并行度

- **P0：GA-01A 的 D-01 / D-02**。先解决单轮 Orchestrator 如何在 Loop 内合法复用以及 M6 test-only 验证边界。没有这个设计，GA-01 实现不得开工。
- **P1：GA-01B**。实现最小循环与 Mock E2E。
- **P1：GA-02 结构探索** 可与 GA-01B 并行，但不能提前冻结全量 Manifest。
- **P2：GA-01C + GA-03**。验证真实模型选择与跨 Domain 可用性。
- **P3：GA-04/05/06**。按风险和真实需求推进；生产 B3/Composition Root 独立跟踪。

不使用“按天完成”的无依据工期承诺；按上述可运行里程碑验收。

## 7. 文档/代码工作规则

- 总体架构只更新 `docs/01-总体架构.md`；实施路线只更新本文件；当前事实更新 `docs/03-开发现状.md`。
- 细节设计只为有独立实现价值的 Unit 新增，历史冻结合同不得被概念性总纲覆盖。
- 单元完成须提交真实代码/测试与链接，并在当前进度文件留下精确 SHA、门禁及 E2E 运行命令。
- 代码未经明确授权不得直接合入 main；文档版本状态不能代替实现认证。
