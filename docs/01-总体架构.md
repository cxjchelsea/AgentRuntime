# 01｜通用 Agent 系统总体架构

**状态：当前目标架构 / 尚未冻结实现契约**  
**依据：main @ `01347c62083cdb30b8a149d37bb979b373ded9d3`（2026-10-09）**

## 1. 产品定义

目标：同一套业务中立的 Agent Core，在装载不同 Domain Package 后能执行差异明显的任务，不修改 Core 源码。Domain Package 不等于简单的 Prompt + RAG，必须能承载工具、工作流、策略、安全规则、状态模型和评测资产。

不在近期目标：生产医疗诊断、自动外部副作用授权、复杂多 Agent 分布式系统。

## 2. 模块与依赖边界

```text
Application / Composition Root
  ├─ Agent/Domain 选择、鉴权、会话、UI/API、部署
  └─ 装配 Domain Package（版本固定、依赖验证）
       ├─ Prompt、Knowledge、Model Route
       ├─ Rule / Policy / Workflow / Capability
       ├─ Domain State / Memory Policy / Eval
       └─ 显式暴露可用动作及执行权限
                  │
                  ▼
General Agent Core  [待建立闭环]
  ├─ Agent Loop Controller（轮次、Budget、停止）
  ├─ Decision Adapter（复用 M3/M4）
  ├─ Observation Adapter（M5/M6 事实投影）
  └─ Replan/Finish Controller（事实驱动；不越权）
                  │
                  ▼
Agent Runtime  [大量已有]
  ├─ M0/M1：生命周期、输入与上下文
  ├─ M2：Safety / State / Policy
  ├─ M3：Understanding Engine
  ├─ M4：Planner / Validator / Rechecker
  ├─ M5：执行、权限、可靠性、幂等、锁、恢复
  ├─ M6：验证相关；当前 G1/G2 只实现 Deny-Only 受限集成
  └─ Registry / Trace / Context / State / Contract
```

**边界提醒**：上图是职责分层，不要求把已有 M3/M4 物理迁移到新目录。它们仍留在 `runtime/`，由 Agent Core 通过明确接口复用。避免同时维护两套 Planner、Execution Engine 或状态控制器。

## 3. 一次 Agent 任务的目标数据流

1. Application 确定会话、身份、Domain Package 的**精确版本**。
2. Context Builder 构造本轮可用上下文，Memory 仅由经过授权的 Adapter 提供。
3. M3 将输入转为结构化理解，不赋予工具执行权。
4. M4 根据目标、Policy 和候选能力提出 ActionPlanDraft，经 Validate + PolicyRecheck 获得 ApprovedActionPlan。
5. M5 仅按已批准计划执行，输出可追踪 ExecutionResult / 执行状态；副作用执行权限不能从 LLM 文本推导。
6. M6 或被明确授权的验证路径给出经过校验的执行事实。
7. Observation Adapter 将**可信、可归因**的事实提供给下一轮决策；UNKNOWN/WAITING 不得被升级为 SUCCESS。
8. Loop Controller 根据停止条件、上限与结果决定继续、Replan、等待人工或终止。
9. 最终响应和状态更新仅依赖可信事实并通过授权边界。

## 4. 决策与确定性控制

| 事项 | 主要责任 | 是否可由 LLM 直接授权 |
|---|---|---|
| 解释用户目标 / 消歧 | M3 + 模型（必要时） | 不能 |
| 从合法候选选择动作 | M4 HybridStrategySelector | 只能建议 |
| 计划校验与批准 | M4 Validator + PolicyRechecker | 不能 |
| 工具选择与执行 | 已批准计划 + M5 Resolver/Executor | 不能 |
| 执行事实与结果验证 | M5 / M6 | 不能 |
| 是否继续/重规划 | 新 Loop Controller（以可信 Observation 为输入） | 可建议，不可越过硬约束 |
| 超时、预算、取消、锁、权限 | Runtime | 不能 |
| 完成判定 | Loop Controller + 确定性完成条件 + 经验证事实 | 不能凭空宣布成功 |

## 5. Agent Loop 的最低接口设计方向

```text
AgentRunInput -> [DomainBinding, TurnContext, Budget]
  -> UnderstandingState -> ActionPlanDraft -> ApprovedActionPlan
  -> ExecutionResult -> ValidatedObservation
  -> {CONTINUE | REPLAN | WAIT | FINISH | BLOCK}
  -> AgentRunOutcome
```

上述 `ValidatedObservation`、`AgentRunOutcome` 是**候选新类型名**，还不是已冻结 Canonical Contract。设计时应优先通过 Adapter 承接既有 `RuntimeInput`、`RuntimeContext`、`UnderstandingState`、`ApprovedActionPlan`、`ExecutionResult`、`ValidatedResult`；不得无审查改动冻结合同。

停止规则至少包括：完成条件得到事实支持、明确失败/安全阻断、最多迭代次数、最大工具调用次数、总超时/Token 预算、人工等待、模型重复动作/无进展检测。

## 6. Domain Package 装配边界

候选结构：manifest + prompts + knowledge binding + capabilities/tools + workflows + policies + state/memory policy + eval。设计中明确：

- Domain 版本和其依赖版本固定，不接受执行中静默切换。
- Registry 现有登记行为不等于实际资产装配；需建立 Loader/Assembler 并验证双 Domain。
- identity / session / domain / version 共同构成数据与缓存作用域；跨 Domain 不泄露 Knowledge 和 Memory。
- 禁止 Domain 扩展覆盖 Core 安全和真实执行权限。
- 测试先采用教育与通用资料问答等低风险场景，避免把医疗真实副作用当首个演示。

## 7. M6 的现实限制

当前 `runtime/orchestration/runtime.py` 的 `DENY_ONLY_GATED` 在结果验证后执行 Block；`LEGACY_TEST_COMPAT` 为旧测试兼容模式。**两者都不能自动作为生产正向授权的解决方案。**

GA-01 要求仅在隔离/模拟工具/无真实副作用的测试路径验证 Loop；需要新明确测试边界及负向测试，禁止把生产执行注入该测试路径。生产路线仍需要 M6 B3、Composition Root 等独立证据。
